# ACCEPTANCE

Что проверено на самом деле и что ещё нельзя считать проверенным. Дата проверки: 2026-10-01.

## Среда проверки

В этой среде не было ни проекта Supabase, ни доступа к Vercel, ни Docker, ни реального телефона. Поэтому всё ниже проверено так:

- **База:** обычный PostgreSQL 16 с теми же миграциями, что поедут в Supabase. `supabase/local/shim.sql` добавляет то, что в Supabase есть из коробки: роли `anon` / `authenticated` / `service_role`, `auth.uid()`, `auth.users`, `storage.objects`.
- **API:** локальный шлюз `scripts/local/gateway.ts` (REST/RPC, Auth с паролем и JWT, Storage, прокси на Functions). Это эмулятор Supabase, а не Supabase.
- **Edge Function:** настоящий код под Deno 2.9.
- **Push-сервис:** тестовый HTTP-сервер, который принимает и расшифровывает сообщения. Это не FCM, Mozilla autopush и не Apple.
- **Браузер:** Chromium через Playwright, профили iPhone 13 (мобильный) и десктоп 1366×900.

**SQL** (`tests/db`):

*Слоты и расписание*
- Слоты строятся по сетке внутри рабочих часов, с учётом перерывов, выходных, особых дат, часового пояса студии (Екатеринбург, UTC+5) и минимального запаса до записи.
- Двухдневная работа занимает пост непрерывно, вместе с буфером.
- Буфер между машинами учитывается.
- Блокировки владельца учитываются.

*Запись*
- Цену, длительность и пост определяет сервер. У клиента нет параметров, которыми он мог бы их передать.
- Токен записи хранится только как хэш.
- Повтор запроса с тем же ключом возвращает ту же запись и тот же токен. Двойной клик создаёт одну запись.

*Гонки*
- Одна услуга с одним постом: из параллельных клиентов выигрывает ровно один.
- Услуга с двумя постами: выигрывают ровно двое, и на разных постах.

*Отмена и перенос*
- Клиент отменяет запись в пределах правил, после этого время снова свободно.
- После дедлайна отмена запрещена.
- Перенос атомарный: при неудаче исходная запись остаётся как была. Двухдневную работу можно перенести на другой день.

*Ограничение частоты*
- Лимит по IP считается атомарно, неудачные попытки тоже идут в счёт.

*Цены, оплаты, статистика*
- Историческая цена сохраняется после изменения услуги.
- Статусы, оплаты, возвраты (не больше оплаченного) и статистика считаются в SQL.

*Очередь напоминаний (outbox)*
- Ровно одно напоминание, повторная подписка не создаёт дубль.
- Перенос и отмена пересоздают или отменяют напоминание.
- Аренда задания: одно задание не уходит двум обработчикам, просроченная аренда переходит другому.
- В preview напоминания подавляются.
- Запись меньше чем за 24 часа честно отвечает `too_late`.

*Изоляция и права*
- `anon` не имеет доступа к таблицам и не может вызвать функции владельца, конвейера и рассылки.
- Владелец не видит и не меняет чужую студию ни через одну функцию.
- RLS отдаёт только строки своей студии и никогда не отдаёт хэши токенов.
- Составные внешние ключи отклоняют ссылки между студиями даже от `service_role`.
- Storage пускает владельца только в папку своей студии.
- В публичном ответе нет персональных данных.

*Конвейер*
- Две студии публикуются рядом.
- Повторная публикация сохраняет записи, фото и правки владельца.
- Переход в live удаляет только демо-записи.
- Отключённая студия не отдаётся.

**Web Push** (`supabase/functions`):
- Сообщение шифруется по RFC 8291, и подписчик его расшифровывает. Для каждого сообщения новая соль и новый серверный ключ.
- VAPID JWT подписан по RFC 8292.
- Ответ 410 означает «подписка умерла».
- Функция `notify-dispatch` под Deno отклоняет вызов без секрета cron. Созревшее напоминание она отправляет зашифрованным, удаляет умершие устройства, повторно не отправляет.

**e2e** (Chromium, телефон и десктоп):

*Запись клиентом* (`booking.spec.ts`):
1. Стеклянная кнопка, затем услуга и свободный слот.
2. Валидация контактов, проверка, «Вы записаны», «Моя запись».
3. Вход владельца: запись видна в его списке.
4. «Автомобиль принят», оплата 3 500 ₽, выход.

*Изоляция студий* (`tenants.spec.ts`):
- Каждая студия показывает свои данные.
- Владелец GRAPHITE на `/s/kolesnyi-dvor/owner/` получает «Нет доступа к этой студии».
- Неизвестная студия показывает «не найдена».

*PWA на собранном сайте* (`pwa.spec.ts`):
- У каждой студии свой манифест: `id`, `start_url` и `scope` равны `/s/<slug>/`.
- Глубокая ссылка `/s/<slug>/my` отдаёт оболочку своей студии.
- Service worker зарегистрирован в области студии.
- Все кэши принадлежат ровно одной студии.
- После первого визита оболочка открывается офлайн.

*Правки владельца* (`owner-settings.spec.ts`):
- Замена фото первой карточки галереи, новая подпись второй и новая карточка.
- На публичной странице остальные карточки сохранили фото, подпись и место.
- Новая цена услуги видна клиентам.

## Не проверено: нужны внешние доступы

Это нельзя считать работающим, пока не выполнено на реальной инфраструктуре:

0. **`pnpm supabase:deploy`** (Management API: миграции, auth, секреты, Vault, деплой функции) написан, проверен типами, но ни разу не запускался: сеть этого окружения закрыта для `api.supabase.com`.
1. **Supabase.** `supabase db push` миграций на настоящий проект: в Supabase свои версии расширений, свои права на `auth`/`storage` и своя схема `vault`. Возможны правки миграций.
2. **Supabase Auth.** Вход владельца через настоящий GoTrue, обновление токена, ответ на неверный пароль. Выключенная регистрация в Dashboard.
3. **Supabase Storage.** Загрузка через настоящий Storage API с политиками из миграции, публичные URL картинок.
4. **pg_cron + pg_net + Vault.** Задание `notify-dispatch` по расписанию реально вызывает функцию.
5. **Edge Function в облаке.** `supabase functions deploy notify-dispatch --no-verify-jwt` и вызов с секретом.
6. **Реальная доставка push.** Chrome на Android (FCM), Firefox (autopush), Safari и iOS 16.4+ как установленное PWA (Apple Web Push). Шифрование и VAPID проверены только против тестового сервера.
7. **Vercel.** Сборка на их билд-машине (`sharp`, pnpm, Node 22). Поведение `vercel.json` (файлы раньше rewrites, `404.html` для неизвестных путей, заголовки): правила написаны по документации и проверены только локальным эмулятором `scripts/local/serve-dist.ts` (режимы Vercel и Cloudflare Pages).
8. **`pnpm tenant:verify <slug> --site https://….vercel.app --activate`** против развернутого сайта.
9. **Установка на реальные устройства.** iOS Safari «На экран Домой» (иконка, заставка, safe area, клавиатура), Android Chrome (установка, maskable-иконка). Две студии рядом как два приложения.
10. **liquid-gl на реальных GPU.** В тестовом Chromium WebGPU недоступен, работал WebGL. Резервное CSS-стекло проверено только визуально.

Также не сделано:
- нагрузочное тестирование;
- аудит доступности со скринридером (фокус, aria-метки и reduced motion сделаны, но со скринридером не проверялись).
